# LARP A-02 Governance Bridge — Implementation Test Report v0.1

Status: IMPLEMENTATION PASS / HUMAN-GATED EXTERNAL VERIFICATION PENDING

## Scope

This build adds the smallest governed bridge from an existing `PROPOSED` runtime proposal to an accepted semantic event.

The bridge is intentionally **not exposed as an MCP tool**. A coding agent may propose, but application requires a pre-existing approval receipt whose actor kind is `HUMAN`.

```text
MCP coding agent
  -> larp_propose
  -> proposal receipt only

human control plane
  -> explicit approval receipt

apply-approved-proposal control CLI
  -> deterministic validation
  -> semantic validation receipt
  -> semantic transaction
  -> SemanticEvent
  -> projection fixture update
```

Covered cases:

1. no approval => zero mutation (`HUMAN_APPROVAL_REQUIRED`)

7. same canonical input with injected time/IDs yields the same logical event/validation receipt
8. unsupported command rejected even with approval
9. control CLI consumes an existing approval receipt file instead of synthesizing approval

## Authority boundary

This implementation does not treat the project JSON fixture as canonical semantic history after application. The accepted semantic-event journal is written before refreshing the JSON projection fixture; the projection is considered rebuildable test material for this adapter prototype.

This does not replace the previously accepted SQLite persistence boundary for production-grade atomic semantic transactions.

## A-02 verification still required

A-02 is **not VERIFIED** by these tests alone.

The external gate must use the real A-01 proposal already committed in GitHub, then:

1. a human explicitly approves that concrete proposal;
2. the approval receipt is committed by the human-control side, not generated by the coding agent;
3. Codex consumes that receipt through the control CLI;
4. deterministic validation succeeds against the unchanged proposal/project versions;
5. a `decision.changed` SemanticEvent is emitted;
6. the proposal, approval, validation, transaction and event receipts are committed as test evidence;
7. ChatGPT independently verifies the committed evidence on GitHub `main`.

Until then, A-02 remains ACTIVE / HUMAN GATE PENDING and roadmap coverage stays 80/100.
